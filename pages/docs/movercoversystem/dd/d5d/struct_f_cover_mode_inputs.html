Detailed Description

Input data describing the cover surface the character is currently snapped to.

Populated each tick by UMoverCoverComponent and injected into the Mover input collection via AddCoverInputsToCollection. UCoverWalkingMode reads this struct in GenerateMove_Implementation to produce cover-locked movement.

float FCoverModeInputs::BlockedShimmyDirection = 0.0f

Sign (+1 or -1) of the shimmy direction that the lookahead trace was checking when it failed. Determines which peek distance and rotation direction to use at the wall edge.

◆ bShouldBeInCoverMode

bool FCoverModeInputs::bShouldBeInCoverMode = false

Persistent flag indicating the character should be in Cover mode. Set to true by UMoverCoverComponent::TryEnterCover and false by ExitCover. Read every simulation tick by UCoverEntryTransition (Walking → Cover when true) and UCoverExitTransition (Cover → Walking when false). Using persistent state rather than one-shot flags avoids timing issues between TickComponent and the Mover simulation's ProduceInput call.

◆ bSideWallDetected

bool FCoverModeInputs::bSideWallDetected = false

Whether a perpendicular wall was detected beside the character on the shimmy side, indicating a concave corner ahead. UCoverWalkingMode transitions the character's facing toward it as they shimmy in.

◆ bWantsToAim

Whether the player is holding the aim input. When true and bHasValidWallAhead is false, the character peeks out to RightEdgePeekDistance / LeftEdgePeekDistance from the wall edge.
